# Sentinel Sunday Demo — DEMO_SCRIPT.md

**Lane 3 (demo narrative + rehearsal) · 2026-10-03**
**Reconciled with Aditya's no-fake law.** The engine is REAL: every decision
in this demo is computed live by the real `Gate` + race-to-page, answered by
the REAL Jev System One API (`jev-1.13.0`, auth via the `custom.typesafe`
connector — the raw key never enters the demo process). Synthetic ALERT
TRAFFIC only — a demo is not production data.

> **Nothing here is hardcoded. No mock engine in the demo path. No
> pre-baked outcomes.** If the Jev credential is absent, the runner stops
> and says so on screen (exit 2) — it never silently falls back to a mock.

## How to run the demo

```bash
cd ~/workspace/jev-builds/sentinel
PYTHONPATH=src python3 demo/storm-scenario/storm_runner.py \
    --n 40 --seed 42 \
    --db demo/storm-scenario/storm.db \
    --out demo/storm-scenario
```

The runner drives the storm through the real engine, prints the river to
the terminal (screen-share it), and writes three artifacts to
`demo/storm-scenario/`:

- `storm.db` — the append-only, hash-chained event log (the source of truth)
- `storm-report.json` — the real projection over the log (decisions,
  budget outcomes, latencies, flips, head hash)
- `event-log.jsonl` — the log, exportable, grep-able

**Runtime:** ~41 real Jev calls at ~2 s spacing ≈ 5–7 minutes total.
**Cost:** ~41 × small System One calls (trivial; $0.042/M input tokens).

**If the API/UI lanes have merged** (platform tier serving the frozen
`GET /api/decisions` read API from SQLite + the Prism UI), the demoist
presents from the UI and cites the same event log as the data source.
**If not**, the terminal river + these beats are the presentation —
polished, honest, complete. Every beat below names both.

## Beat 1 — The designed flip (the machine being wrong first, at minute 1)

**What happens:** the runner fires one known-noise alert (the storm's
first flap) at a gate whose race budget is **B=500 ms** — deliberately
below Jev's measured p50 (~815 ms, Oracle N=100 campaign). The timer
wins. The page goes out. The budget held; the vendor's tail did not
decide.

Then the late real Jev answer lands — as a `shadow_decision`, never
acting, always recorded. The river shows the fold:

```
▮ <time> · redis-cache · PASS-THRU · timer_won · 500ms
  ↳ late answer: q1=0.00 conf=0.67 disposition=page_business_hours —
    the machine's own second opinion, recorded, never acting
```

**Say this:** "We gave the machine a budget it could not meet. It paged
— the safe default. Then its own late answer arrived and said:
page_business_hours, not suppressible. The machine disagreed with itself,
in the open, in front of you, at minute one. That is not a bug we are
apologizing for. That is the product: every disagreement the machine has
with itself is written to the event log and shown, not smoothed over."

**The honest re-ask (same beat, 30 seconds later):** the same alert goes
through the real gate again at B=2700 ms, twice. Present both
dispositions exactly as they land:

- If identical (the modal outcome, ~98%): "Same answer twice. That is the
  modal outcome. Jev flips on 1.3–2.2% of re-asks — the floor is measured,
  not promised. The flip-audit view holds every one we've ever seen."
- If they differ: "There it is — a real flip, live, unscripted. Same
  input hash, two different answers. The log holds both; nothing was
  rewritten."

**Reads (UI path):** `GET /api/decisions?limit=50` + `SSE /api/stream`.
**Strip:** *"The budget fired first: the page went out. The machine's
late answer is recorded below — it never acts."*

**Exit condition:** the viewer has seen the timer win and the late
answer, and can say what a shadow decision is. ("The machine showed me a
failure before asking for trust.")

## Beat 2 — The storm + the real Shadow Report

**What happens:** the remaining 39 alerts fire through the real gate at
B=2700 ms. The river fills with real dispositions — pages, queues,
passthroughs — each row carrying the real budget outcome
(`answered_in_time` / `timer_won`), the real Jev latency, the real model
version.

**At the end, the runner folds the event log into the report.** This is
the Shadow Report for the storm — not a mockup, a projection:

- decisions by disposition (e.g. `page_now: N, passthrough: N, …`)
- budget outcomes (`answered_in_time` vs `timer_won` — the race, counted)
- real Jev latencies (min / p50 / max, model `jev-1.13.0`)
- flips from `detect_flips()` — disposition flips vs confidence wobbles,
  named separately
- the log's head hash — the receipt that this report is *this* log

**Say this:** "Every number I just read came from the event log on this
machine — not from a slide. The head hash is the proof: re-run the fold,
you get the same numbers."

**The triple-lock honesty beat (delivered inside beat 2):** if the storm
produced zero suppressions, say so proudly — do not hide it: "Tonight the
engine suppressed nothing. The suppression bar is a triple lock —
reported P(p1) exactly 0.00, confidence ≥ 0.90, dual-attested allowlist.
The lock held on every alert. A demo that manufactured a suppression
would be the fake we refused to build."

**Reads (UI path):** `GET /api/decisions?limit=50`,
`GET /api/calibration?team=…`, `GET /api/analytics/flips?window=7d`.
**Strip:** *"{n} decisions, {p} pages, {s} suppressions, {t} timer wins.
Every number traces to the event log."*

**Exit condition:** the viewer has seen the river move and can say where
the report's numbers come from. (The event log.)

## Appendix B — What this demo deliberately does NOT show

- No fabricated 11-month backtest (beat 4 says so out loud).
- No production-vs-shadow divergence ledger (needs the stage-1 shadow
  tap against a real vendor stream; beat 3 shows the mechanism on the
  machine's own flips).
- No canary stage machine beyond the live thresholds (the deployment
  state machine is a design; the demo shows the controls that exist).
- No suppression receipts unless the engine really suppressed.

*The demo's persuasiveness is its own adversary (design 08 §0). The
defense is this script: every claim traceable, every absence stated.*
